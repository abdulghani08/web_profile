# Content Model and Asset Policy

## Proposed content entities

### Profile
- Name
- Primary role/headline
- Summary in English and Indonesian
- Location at the level the owner approves
- Verified professional links
- Contact method(s)

### Experience item
- Organization
- Role
- Start/end date or current status
- Work arrangement/context, if approved
- Responsibilities
- Evidence-backed achievements
- Language variants

### Project
- Stable slug/identifier
- Title and short summary in both languages
- Category
- Status (production, prototype, academic, personal, or unknown—only when confirmed)
- Role and contribution
- Verified technologies
- Context/problem
- Work performed
- Outcomes/evidence
- Public links
- Media and alt text
- Disclosure/permission status

### Skill
- Name
- Category
- Evidence reference (project/role)
- Optional context level, only if meaningful and approved

## Asset policy

- Use only assets owned by the owner, licensed for use, or approved by the relevant party.
- Verify rights and permission for logos, screenshots, client marks, app images, and team photos.
- Remove or mask names, student records, email addresses, IDs, tokens, and other private data from screenshots.
- Do not commit credentials, production dumps, private API responses, or environment files.
- Provide meaningful alt text for informative images; decorative images use empty alt text where appropriate.
- Optimize image dimensions and formats during implementation.

## Evidence traceability

Maintain a private working checklist linking each public factual claim to the CV or owner confirmation. Do not publish private verification notes.
