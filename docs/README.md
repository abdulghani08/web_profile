## How to use these documents

1. Read `01-project-understanding-lock.md` first.
2. Read `02-project-overview.md`, `03-positioning-and-brand-strategy.md`, and `04-scope-and-requirements.md`.
3. Use `15-development-phases.md` and `16-phase-gate-and-audit-protocol.md` to control project progression.
4. Treat decisions explicitly marked **PENDING DECISION** or **PROPOSED** as unresolved. Do not infer approval.
5. When the repository is available to the implementation agent, the agent must audit the actual repository before proposing or changing code.
6. Read `27-phase-1-gate-review.md` before treating Phase 1 as closed, `29-blocker-register.md` before any gate decision, and `28-phase-2-execution-plan.md` before starting Phase 2. None of these documents authorizes implementation.

## Status vocabulary

- **APPROVED** — explicitly accepted by the project owner.
- **PROPOSED** — recommendation awaiting approval.
- **PENDING DECISION** — unresolved; must not be treated as settled.
- **DEFERRED** — explicitly postponed with Owner approval and a recorded destination phase/gate.
- **VERIFIED** — checked against a reliable source or actual implementation.
- **ASSUMPTION** — temporary working assumption that must be tested.
