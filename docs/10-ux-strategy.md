# UX Strategy

## Core experience principles

1. **Clarity before novelty:** visitors should understand the owner's role and strengths immediately.
2. **Evidence before decoration:** project detail and verified contributions should carry the story.
3. **Progressive disclosure:** concise overview first, deeper technical detail on project pages.
4. **Low-friction navigation:** clear labels, sensible page hierarchy, visible contact route.
5. **Accessible by default:** keyboard support, focus indicators, semantic structure, readable contrast, reduced-motion support.
6. **Bilingual parity:** neither language should feel incomplete.
7. **Mobile-first validation:** navigation, text, case-study media, and calls to action must work on narrow screens.

## Key journeys

### Recruiter
Home → Experience or Projects → relevant project detail → Contact / professional profile.

### Engineering lead
Home → Projects → Case study → Skills/Experience → Contact.

### Potential client
Home → relevant work → explanation of capabilities → Contact.

### Indonesian visitor
Any page → language switch → equivalent Indonesian page when available.

## UX risks

- Too many competing professional identities.
- Too many project cards without depth.
- Long paragraphs and technology lists with no context.
- Contact links that do not work.
- A language switch that loses page context.
- motion or effects that slow down or distract from content.

## Validation

Use manual task-based review with representative journeys during Phase 7. Record observed issues, severity, reproduction steps, and disposition.
