# Project Overview

## Summary

Create a bilingual, professional software developer portfolio that converts experience and project work into clear evidence of capability. The site should serve career opportunities first while remaining useful for client and collaboration inquiries.

## Product objectives

1. Establish one clear primary professional identity.
2. Help visitors quickly understand skills, experience, and project relevance.
3. Show selected work through concise project summaries and, where evidence permits, deeper case studies.
4. Make contact and profile navigation straightforward.
5. Maintain high content credibility and technical quality.

## Desired visitor outcomes

- A recruiter can understand the candidate's profile and relevant experience quickly.
- An engineering lead can identify technical areas and inspect project evidence.
- A potential client can understand the kinds of problems the owner has worked on and find a contact route.
- An international visitor can use the English version; an Indonesian visitor can use the Indonesian version.

## Constraints

- Evidence available initially is primarily the supplied CV and information the owner subsequently confirms.
- Public access to project screenshots, source code, production URLs, and client permission has not yet been verified.
- The portfolio must not expose sensitive user data or confidential implementation details.
- The implementation stack and hosting have not yet been selected.

## Non-goals

- Building a full CMS or complex backend unless a validated need emerges.
- Recreating or exposing internal systems described in case studies.
- Claiming unverified traffic, performance, revenue, conversion, or impact metrics.
- Treating every project in the CV as equally prominent.
- Beginning implementation before planning and architecture gates are passed.

## Success measures (initial proposals)

- Every published factual claim has a source or owner confirmation.
- A visitor can reach projects, experience, and contact from primary navigation.
- Both language versions have equivalent essential content.
- No broken internal links or critical responsive defects at release.
- Production build and release checks pass.
- Core SEO metadata and accessibility checks are completed.
- Final quantitative performance thresholds are set in Phase 2/3 and measured in Phase 7.
